# Cafe Order + POS คาเฟ่ (หลายร้าน)

| เส้นทาง | คืออะไร |
|---|---|
| `/` (`index.html`) | หน้าแรก Easy POS (landing) · ลิงก์เดิมที่มี `?t=` `?o=` จะถูกส่งต่อไป `/order` |
| `/s/<รหัสร้าน>` (`order/index.html`) | หน้าสั่งอาหารของลูกค้าแต่ละร้าน (`/order` เฉย ๆ ใช้ร้านแรก) |
| `/retail` | หน้าเข้าสู่ระบบ Easy POS Retail (กำลังพัฒนา) |
| `/pos` | POS ของร้าน ต้องเข้าสู่ระบบ ผู้จัดการ/พนักงานเห็นเฉพาะร้านตัวเอง |
| `/admin` | แดชบอร์ดผู้ดูแลระบบ: สร้างร้าน กำหนดผู้จัดการ/โควตาพนักงาน ค่าบริการรายเดือน ตรวจสลิป |

## โครงสร้างข้อมูล (Supabase)

- `pos_shops` ร้านค้า (รหัสร้าน ราคา/เดือน โควตาพนักงาน วันหมดอายุ สถานะ)
- `pos_members` บัญชีในร้าน (ผู้จัดการ 1 คน + พนักงานตามโควตา) หนึ่งอีเมลอยู่ได้ร้านเดียว
- `pos_data` ข้อมูล POS แยกตาม `shop_id` (เมนู โต๊ะ ออเดอร์ ตั้งค่า) อัปเดตเรียลไทม์
- `cafe.shop_state` / `cafe.orders` เมนูและออเดอร์จากแอปลูกค้า แยกตามร้าน
- `pos_payments` การแจ้งชำระค่าบริการ (สลิปอยู่ใน bucket ส่วนตัว `pos-slips`)
- `pos_admins`, `pos_platform` ผู้ดูแลระบบและบัญชีรับค่าบริการ
- สิทธิ์ทั้งหมดบังคับด้วย RLS: ร้านอ่าน/เขียนได้เฉพาะ `shop_id` ของตัวเอง ร้านที่หมดอายุเกินช่วงผ่อนผันหรือถูกระงับจะเขียนข้อมูลไม่ได้
- ตารางเดิม `pos_docs`, `pos_staff`, `cafe.state` เก็บไว้เป็นสำเนา อ่านได้เฉพาะผู้ดูแลระบบ

SQL ของการย้ายเป็นหลายร้านอยู่ที่ `supabase/migrations/pos_multi_shop.sql`

## แก้ไข POS

ซอร์สหลักคือ `src/cafe-pos.artifact.html` แล้วสร้างเวอร์ชันเว็บด้วย

```
python3 tools/build_pos.py
```

ซึ่งจะเขียน `pos/index.html` โดยเพิ่มระบบล็อกอิน ฐานข้อมูลรายร้าน และหน้าค่าบริการจาก `tools/standalone-shim.html`
